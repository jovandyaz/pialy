# Pialy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A public web app where a customer holds an appointment slot by paying a $0.01 CoDi deposit through pey, and the owner's board confirms it live, built on a reusable, rail-agnostic payments core.

**Architecture:** pnpm monorepo. `packages/payments` (pure domain + use cases + ports, reusable by Seeb), `packages/connector-pey` (RailConnector for pey), `apps/server` (Fastify modular monolith: booking, business, realtime, http; Drizzle on Postgres; outbox → SSE; sweeper), `apps/web` (React SPA served by the server). One Railway service + Railway Postgres.

**Tech Stack:** Node 24, TypeScript (strict), pnpm, Fastify 5, Drizzle ORM 0.45 + drizzle-kit + `postgres` driver, Zod 4, `standardwebhooks` 1.1, pino 10, Vitest 5, React 19 + Vite 8 + React Router, `qrcode`, Fontsource Archivo + Doto.

**Spec:** `docs/superpowers/specs/2026-11-14-pialy-design.md` (read §5b and §6–§9 before any task). UI source of truth: `design/mockups/pialy.html`. Product record: `PRODUCT.md`.

## Global Constraints

- Every charge is exactly 1 minor unit (MXN $0.01), set server-side from `DEMO_DEPOSIT_CENTS=1`; no endpoint accepts an amount.
- pey base `https://api.pey.mx`, `Authorization: Bearer ${PEY_API_KEY}`. Push: `POST /codi/pn` `{amount, phoneNumber (^[0-9]{10}$), concept, expiration (>=360), numRef (^[0-9]{1,7}$), metadata (<=50 scalar pairs)}` → `{transactionId, codiId}`. QR: `POST /codi/qr` `{amount, concept, expiration (0 or >=360), numRef, metadata}` → `{id, qrString}`. Status: `GET /transaction/{id}` → `status: PENDING|PAID`; `GET /transaction/codi/qr/{id}` → `{items[], nextToken}`.
- Webhooks: Standard Webhooks headers `webhook-id`, `webhook-timestamp`, `webhook-signature`; events `codi.pn.payment_received`, `codi.qr.payment_received`; payload fields per spec §3.
- Hold length = attempt expiration = 360 s. Sweeper interval 15 s. Late-payment watch 30 min after expiry. Max 3 attempts per booking.
- A booking/payment becomes paid only via verified webhook or connector status query. Never from the client.
- Secrets only in env (`.env` locally, Railway variables in prod). Never log `PEY_API_KEY`, `PEY_WEBHOOK_SECRET`, full phone numbers. Persist phone as `phone_last4` + `phone_hash` (HMAC-SHA256 with `PHONE_HASH_SALT`).
- Domain code (`packages/payments/src/domain`, `apps/server/src/modules/*/domain`) imports nothing from Fastify, Drizzle, `fetch`, or `Date.now()`; time comes from a `Clock` port.
- TypeScript `strict`, `noUncheckedIndexedAccess`, no `any`. Zod at every edge (HTTP bodies, env, pey responses, webhook payloads).
- UI copy in Mexican Spanish only. Name "Pialy"; never "pey"/"CoDi" in the product name. Business shown: "Estudio Demo" (synthetic).
- Time zone for slots and display: `America/Mexico_City`.
- Conventional Commits, single line, English, no trailers. Licence FSL-1.1-MIT.

## Review Focus

1. Customer double-taps "Enviar solicitud" or the network retries → exactly one hold and one push (Idempotency-Key). Test in Task 6.
2. Two customers request the same slot at the same instant → one 201, one 409 with "Ese horario se acaba de ocupar". Test in Task 6.
3. pey's webhook arrives before the attempt row has stored `transactionId` (pey answers fast) → correlation falls back to `metadata.attemptId`; payment still applies once. Test in Task 5.
4. Phone typed as `55 1234 5678`, `+52 5512345678` or `044…` → normalized to 10 digits or rejected with a clear message. Test in Task 6.
5. Server runs in UTC while slots are shown and generated in `America/Mexico_City` → 09:00 local is stored as 15:00Z (CST, UTC−6) and rendered as 09:00. Test in Task 6.
